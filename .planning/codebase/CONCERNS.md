## 1. Technical Debt & Current Bottlenecks

### A. HTTP Polling vs. WebSockets (Phase 5 Target)
- **Current State:** The Next.js dashboard polls `/jobs` every 3000ms and `/events` every 2000ms.
- **Concern:** Introduces up to 2 seconds of visual latency between worker task completion and terminal rendering. Multi-tab browsing creates redundant HTTP request overhead.
- **Remediation:** Implement native FastAPI WebSocket endpoint (`/ws/jobs/{id}`) and hook up client listener with automatic reconnection.

### B. Single Master Orchestrator (SPOF)
- **Current State:** A single FastAPI master coordinates all task partitioning, job tracking, and MinIO uploads.
- **Concern:** If the master node crashes, active worker nodes continue listening to RabbitMQ but cannot report progress or register heartbeats.
- **Remediation:** Acceptable for a capstone edge cluster prototype. For production scaling, deploy multi-master orchestrator instances with a shared Mongo replica set and RabbitMQ cluster.

### C. GPU VRAM Memory Pool Fragmentation
- **Current State:** CuPy uses a custom memory pool that retains allocated VRAM blocks to accelerate subsequent operations.
- **Concern:** Processing batches of large images without releasing device memory can trigger CUDA `Out of Memory` (OOM) errors on consumer GPUs with $\le 6\text{ GB}$ VRAM.
- **Remediation:** Explicit `cp.get_default_memory_pool().free_all_blocks()` must be called in `finally:` blocks following every GPU convolution or matrix multiplication.

## 2. Security & Trust Boundaries

### A. Untrusted Volunteer Execution
- **Current State:** Workers execute pre-defined Python strategies inside Docker containers.
- **Concern:** Malicious volunteer nodes could theoretically tamper with intermediate results (e.g., returning invalid matrix blocks).
- **Remediation:**
  - Strict Docker sandboxing (`--cap-drop=ALL`, non-root user).
  - Linux `cgroups v2` memory and CPU limits.
  - Verification hashing: Master validates output checksums and spot-checks random compute slices.

### B. Open Registration Endpoint
- **Current State:** `/api/v1/workers/register` accepts any worker declaring a `worker_id`.
- **Concern:** Rogue clients could register hundreds of phantom nodes to flood the registry.
- **Remediation:** For enterprise grids, implement JWT or pre-shared pool authentication tokens passed via `POOL_TOKEN`.

## 3. Host & Environment Gotchas

- **Windows Hyper-V Port 3000 Bug:** Windows randomly reserves port ranges including 3000 for Hyper-V. The dashboard is configured to use port `5555` to prevent `EADDRINUSE` failures.
- **MinIO Storage Drive Mapping:** `docker-compose.yml` maps MinIO data to `D:\Daemon_Minio_Data`. Machines without a `D:\` drive must adjust this path to `C:\Daemon_Minio_Data` or use a named Docker volume.
- **Docker Desktop on Windows:** Containers must use `--add-host=host.docker.internal:host-gateway` to ensure seamless communication with host services.
