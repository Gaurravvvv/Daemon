## 2. Hardware Probing & GPU Smoke-Test

When a worker starts (`worker/main.py`), it automatically runs `probe_gpu()`:
1. Queries `cupy.cuda.runtime.getDeviceCount()`.
2. Allocates a small test array on the GPU:
   ```python
   test_arr = cp.zeros(2, dtype=cp.float32)
   test_arr += 1.0
   cp.cuda.Stream.null.synchronize()
   del test_arr
   cp.get_default_memory_pool().free_all_blocks()
   ```
3. If successful, logs device name (e.g. `NVIDIA GeForce RTX 3060 Laptop GPU`) and VRAM size; otherwise, falls back cleanly to CPU mode.

## 3. End-to-End Functional Test Procedure

1. **Boot Core Grid:** Run `start_grid.bat` or `docker-compose up -d`.
2. **Launch Orchestrator & UI:** Verify `http://localhost:8000` (FastAPI) and `http://localhost:5555` (Dashboard).
3. **Launch Worker:**
   ```bash
   cd worker && python main.py
   ```
4. **Deploy Test Job:**
   - Go to `http://localhost:5555/orchestrator`.
   - Click **Deploy New Job**.
   - Attach `payload.zip` (10 partitions), choose `Hybrid`, click Submit.
5. **Verify Execution:**
   - Worker claims chunks #1 to #10.
   - Live events appear on UI terminal.
   - Progress ticks from 0% to 100%.
   - Click green **Download Final Result** to inspect the generated ZIP.

## 4. Resilience & Chaos Churn Test

To test fault-tolerant task re-queueing:
1. Deploy a 10-chunk job with 2 active workers.
2. While chunks are processing, press `Ctrl+C` in Worker 2's terminal.
3. Observe Orchestrator log: within 15 seconds, the Redis TTL lease expires, Worker 2 is marked `OFFLINE`, and orphaned tasks are re-queued to Worker 1.
4. The job reaches 100% completion without human intervention.
