## 1. Python Standards & Idioms (Backend & Worker)

### A. Style & Formatting
- **PEP 8 Compliance:** 4-space indentation, clear variable naming, explicit module exports.
- **Type Hinting:** Mandatory type annotations on all API signatures, request models, and partitioning functions (e.g. `List[dict]`, `Optional[str]`).
- **Pydantic Validation:** All incoming and outgoing REST payloads defined as `pydantic.BaseModel` subclasses in `orchestrator/models/schemas.py`.

### B. Asynchronous Patterns
- **FastAPI / Motor:** Asynchronous non-blocking coroutines (`async def`, `await`) are standard for all MongoDB queries, file I/O, and background aggregator loops.
- **Pika & Boto3 Handling:** Because Pika and Boto3 operate synchronously, they are wrapped cleanly inside services (`services/rabbitmq.py`, `services/storage.py`) or executed in isolated execution loops.

### C. Logging & Telemetry Conventions
- **Standardized Logger:** Every module instantiates:
  ```python
  import logging
  logger = logging.getLogger(__name__)
  ```
- **Fire-and-Forget Event Logging:** Workers emit real-time logs via `_emit(job_id, level, message)` wrapped in a broad `try-except` block:
  ```python
  def _emit(self, job_id: str, level: str, message: str):
      try:
          requests.post(..., timeout=3)
      except Exception:
          pass  # Event logging failures must NEVER crash the compute daemon
  ```
- **Log Levels:** `SYSTEM` (registration/join), `INFO` (chunk picked up/processing), `SUCCESS` (chunk completed), `WARNING` (hardware mismatch/fallback), `ERROR` (task failure/exception).

## 2. Frontend Conventions (Next.js & React)

### A. Component Architecture
- **Next.js 15 App Router:** File-system based routing using route groups `(dashboard)`. Server components used by default; `"use client"` declared explicitly at the top of interactive components.
- **Param Resolution in Next.js 15:** Route parameters resolved via React `use(params)` or `await params` (e.g., `const resolvedParams = use(params);`).

### B. Styling & Design System
- **Tailwind CSS Utility Classes:** Consistent use of semantic tokens defined in `globals.css`:
  - `micro-label`: Monospace uppercase small labels for metadata.
  - `ide-chip`: Rounded status badges with glowing status dots (`active-dot`).
  - `card-interactive`: High-contrast dark surfaces with subtle hover borders.
  - `kpi-numeral`: Large, clean numerical indicators for metrics.
- **Color Palette:** Curated dark terminal theme (charcoal/slate background `#0B0F19`, high-contrast emerald `#10B981` for active states, crimson `#EF4444` for halts, cobalt blue `#3B82F6` for orchestrator highlights).

## 3. Data & API Contracts

- **JSON Keys:**
  - Python backend & RabbitMQ payloads use `snake_case` (e.g., `job_id`, `raw_data_url`, `chunk_index`, `total_chunks`, `compute_mode`).
  - TypeScript frontend interfaces mirror backend keys for zero-translation serialization.
- **MinIO Storage URIs:** Formatted strictly as `minio://<bucket_name>/<object_key>`.
- **Worker IDs:** Structured as `NODE-<6_CHAR_HEX>` (e.g. `NODE-A1B2C3`).
- **Job IDs:** Structured as `job-<4_DIGIT_INT>` (e.g. `job-1042`).
